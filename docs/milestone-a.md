## Mac development artifact

- Tauri v2; app version 0.1.0. Executable: Mach-O 64-bit arm64; signature ad hoc (`TeamIdentifier=not set`), not notarized.
- DMG: `apps/desktop/src-tauri/target/release/bundle/dmg/Slide Workspaces_0.1.0_aarch64.dmg`
- SHA-256: `2c2d894d317e7bf2c450419da396cb5d499e425c89c578f2975bf9cb4e1e5fc2`
- App bundle: `apps/desktop/src-tauri/target/release/bundle/macos/Slide Workspaces.app`.
- `hdiutil verify` reported the DMG checksum valid. The installed executable matched the executable on the mounted DMG byte for byte.
- macOS displayed app modification and GoogleUpdater background activity notifications during Chrome startup. Both browser sessions were usable without granting new permissions or disabling any protections. Chrome may also ask to become the default browser; the manager does not require or set a default browser.
- On a downloaded development build, follow your organization's normal approval process if macOS blocks it. No Developer ID, Apple notarization or Windows Authenticode is claimed.
- [CI jobs](https://github.com/bloxy-studios/Slide/actions/workflows/desktop.yml) build separate architecture-specific Mac and Windows development artifacts. An installer build is not an installed-app test.

## Local behavior and limitations

The catalog stores metadata, not browser cookies. Each workspace UUID gets its own Chrome data directory. Browser profile locks belong to Chrome; the manager leaves them in place. An ambiguous lock is shown as **Profile in use**. The manager only sends OS-native focus/close to a PID after verifying the live process birth time and exact `--user-data-dir`. It never force-kills a browser. If a machine or manager was stopped when a browser disappeared, the manager cannot recover the child's exit status and does not label it a proved crash.

If a new Chrome window opens behind the manager, use **Focus** for that workspace. The manager itself uses a trusted Tauri webview, not the selected browsing engine.
