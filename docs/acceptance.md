## Milestone F installed macOS arm64

Built the development DMG, mounted it read-only and copied the app to an isolated QA directory. On macOS 26.6.2 arm64, opened [Support, reviewed the preview and saved diagnostics](evidence/mac-f-support.png). The saved JSON contained only the schema version, app version, platform/OS version, architecture, manual update status, and default browser name, version and bundled flag. The Rust [allowlist regression test](../apps/desktop/src-tauri/src/support.rs) also verifies that executable paths and untrusted metadata are excluded.

Started Folve Creator and Folve Viewer on the same synthetic fixture URL. Both used bundled fingerprint-chromium 148.0.7778.215; the role cookie display, localStorage and IndexedDB markers differed. Viewer logout left its local markers and did not sign out Creator. Both original browser processes kept their PIDs and start times after using **Support → Restart manager**; [the relaunched manager showed both Running](evidence/mac-f-reattached.png). Double-clicking Start on Creator left the original browser processes in place.

Opened the [loopback fingerprint fixture in the installed Viewer browser](evidence/mac-f-fingerprint.png) and observed Chromium 148 Client Hints, CPU and device memory, time zone, canvas hash and WebGL vendor. The opt-in [Bun fixture test](../apps/fixture/server.test.ts) independently checked requested CPU, platform and time-zone settings and differing canvas hashes in two isolated profiles using the same pinned arm64 browser version. The observed vendor does not establish vendor spoofing.

After logging out, closing, and cold-starting Viewer, stopped only the verified disposable Viewer browser process with SIGKILL. Slide reported **Exited unexpectedly** while Creator kept running. **Start** reopened Viewer; reloading the fixture showed the same localStorage and IndexedDB markers, with Viewer still logged out. The isolated QA home presented a missing Chromium Keychain prompt on cold launches; it was dismissed. One native Focus attempt also reported that macOS did not activate the browser; a subsequent Start on the already-running Creator raised its window. The installed screenshots predate a Windows-only version formatting correction in the report.
